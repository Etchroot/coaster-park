# 🎢 코스터 데이터 파크 (초안)

롤러코스터를 **10개 유형**으로 나누고, 유형마다 공원에 존 하나씩 지어 **3D 미니어처 모형 + 3D 막대 그래프 + 개장 연대 그래프**를 세운 놀이공원.
1,000개를 하나씩 모델링하는 대신, 유형 하나에 모형 하나를 만들고 통계는 그 유형에 속한 코스터 전체로 계산해요. (유형 = 데이터 분류, 존 = 공원 안의 구역)

## 실행
```bash
python -m http.server 8765 --directory web
```
→ 브라우저에서 http://localhost:8765 (three.js는 CDN에서 불러와서 인터넷 연결 필요)

데이터를 다시 만들 때:
```bash
python clean.py        # data/coaster_db.csv -> data/clean.csv
python build_data.py   # data/clean.csv -> web/data.js (유형별 통계)
```

## 정제 기록
| 문제 | 칸 | 예 | 고친 방법 |
|---|---|---|---|
| 중복 | coaster_name | 같은 코스터가 이전·재설치로 2~3행 (97행) | 최근 설치(year_introduced 최대) 1행만 |
| 숫자가 글자 | Height · Length · Drop | `"72.5 ft (22.1 m)"` | 괄호 속 m 값을 꺼냄, 없으면 ft × 0.3048 |
| 원본 정제 칸이 거의 빔 | height_ft | 1,087행 중 171행만 값 | 쓰지 않고 Height 글자에서 다시 뽑음 |
| 단위 | speed_mph | mph | × 1.609 → km/h |
| 시간이 글자 | Duration | `"1:32"`, `"2 minutes"` | 초(s) 숫자로 |
| 이상치 | height · speed · length · duration | 단위 오류로 보이는 값 | 높이 > 200 m, 속도 > 260 km/h, 길이 > 3 km, 시간 < 10 s 또는 > 10분은 비움 |
| 표기 불일치 | Type | `Steel – Inverted – Launched` 등 99가지 | 키워드 우선순위로 유형 10개 (마우스 > 스피닝 > 마인 > 플라잉 > 인버티드 > 발사 > 셔틀 > 패밀리 > 우든 > 스틸) |
| 표기 불일치 | Status | `Closed in 2021`, `SBNO …` | 운영중 / 철거·폐쇄 / 기타 |

결측은 채우지 않았어요 → 중앙값은 **값이 있는 코스터만** 쓰고, 화면에 항상 n을 같이 보여 줘요.

## 그래픽
- PBR 환경광(RoomEnvironment) + ACES 톤매핑 + 부드러운 그림자 → 금속 레일·광택 차체가 주변을 반사
- 레일은 금속 + 클리어코트(페인트 광택) + 브러시드 거칠기 맵, 침목·받침은 다크/실버 스틸, 8칸마다 연결 플랜지와 볼트
- 포스트프로세싱 블룸(UnrealBloom) · **🌙 밤 모드** 버튼: 별이 뜬 네온 하늘, 등뼈 아래 네온 스트립과 간판 테두리가 발광, 가로등 점광 + 존마다 스포트라이트 2개
- 열차에는 탑승객이 없고 빈 좌석만 (1인칭 시야 확보)
- 행인은 사이버펑크 스타일: 라떼(lathe) 실루엣 몸통(허리·가슴·어깨), 엉덩이·무릎·어깨·팔꿈치 관절로 걷기(앞으로 나갈 때 무릎 굽힘), 눈꺼풀·홍채·하이라이트·턱·코·귀가 있는 얼굴, 재킷(가죽 클리어코트)·후디·코트·원피스·유니폼, 바이저·헤드폰·마스크·안경, LED 스트립·네온 밑창
- 하늘은 **HDRI**(Poly Haven · CC0, 2K): 낮 `kloofendal_48d_partly_cloudy_puresky`, 밤 `satara_night` → `web/asset/hdri/day.hdr · night.hdr`. 배경과 환경광(PMREM) 둘 다로 써서 실제 하늘빛이 금속 레일·차체에 비쳐요. 로드 전엔 그라데이션 돔이 임시로 보여요.
- 잔디·보도블록은 캔버스로 만든 절차적 텍스처
- 공원 소품: 가로등(불 켜짐) · 벤치 · 화단 · 쓰레기통 · 연석 · 존마다 흰 울타리
- 행인은 캡슐 몸체 + 얼굴(눈·눈썹·코·웃는 입·귀·볼터치) + 어깨·엉덩이 관절, 소품은 손 위치에 맞춰 팔을 올림
- 열차는 둥근 차체(RoundedBox) + 바퀴 + 좌석·머리받침 + 안전바 + 전조등

## 1인칭 탑승 · 자동 테스터
- 카메라는 좌석의 **쿼터니언**을 그대로 따라가요 (`lookAt`은 수직 구간에서 망가져서 안 씀). 트랙 2.2 앞 지점을 살짝 미리 보고, 속도에 따라 시야각이 넓어지고 덜컹거려요.
- 열차 좌표계는 오른손 기저 `x = N×T, y = N, z = T` — 예전엔 `T×N`(왼손)이라 반사 행렬이 되어 좌석이 옆을 봤어요.
- 브라우저 콘솔에서 `__rideTest()`(전체) 또는 `__rideTest(존 번호)`를 치면 각 코스터를 45초씩 시뮬레이션하면서 **시선–진행 방향 각도**와 **머리 주변 0.3 안에 들어오는 부품**(레일·침목·기둥·버팀목·승강장·차트·간판 — 점구름 충돌체)을 세어 줘요. 현재 10개 코스터 모두 `bad=0, clip=0`.
- 트랙 제어점은 Chaikin 코너 컷(1회)으로 둥글려서 V자 골짜기·꼭대기가 곡선이 돼요. 탑승 시야각은 76°(속도 붙으면 최대 94°), 인버티드·플라잉 눈 위치는 레일 아래 0.95~1.05.
- 1인칭에서는 열차를 숨기고 카메라만 트랙을 달려요(차체·안전바·장식이 시야를 안 가림). 시선은 좌석 회전 + 트랙 2.4 앞을 향한 **요/피치 각만** 제한해서 더하고, 그 각과 좌석 회전을 시간 보간(지수 평활)해서 좌우로 탁탁 튀지 않아요. 셔틀은 뒤로 갈 때도 앞(+z)을 보며, 앞서 보기 목표점도 항상 바라보는 쪽이라 시선이 옆으로 돌지 않아요.
- 승강장 구조물(지붕·기둥·펜스·발판)은 모두 뺐어요(시야·외관). 존 이름 간판은 그대로. 인버티드 받침 기둥은 커브 바깥쪽 3.0 거리.
- 테스터는 자기 레일·등뼈와의 거리도 검사하고(여유 0.22), **시야 막힘**(정면 60° 안·1.6 이내·눈높이 이상 부품) 프레임 수도 세요. 승강장은 낮고·곧고·옆에 다른 트랙이 없는 곳에, 데크와 바깥 기둥은 다른 트랙이 더 먼 쪽으로 자동 배치.
- 테스터로 고친 것: 발사형 타워 격자를 머리 바깥으로, 인버티드 루프 주변 받침 생략, 승강장은 가장 낮고 **곧은** 곳에 세우고 기둥은 트랙 위 실제 지점에서 옆으로.

## 소리
- `web/asset/ambience.mp3` — 공원 북적거리는 배경음, 계속 루프 (볼륨 0.45 · 탑승 중 0.2)
- `web/asset/Scream 1~7.wav` — 1인칭 탑승 중에만 4~9초마다(빠를 때 더 자주) 직전과 다른 하나를 랜덤 재생. 작게(0.18~0.26) 그리고 0.12초 페이드인이라 놀라지 않아요.
- 바람 소리는 Web Audio 노이즈로 합성: 속도의 제곱에 비례하고 **내려갈 때 훨씬 세게**(평지의 약 3배), 체인 위에선 거의 없음
- 오르막(체인 리프트)에선 바람 대신 **모터 웅웅 + 래칫 덜그럭**(0.1~0.15초마다 짧은 노이즈 클릭)

## 열차 속도 (물리 느낌)
- `v = k·√(E − 높이)`: 트랙 최고점을 에너지 기준으로 삼아 낮을수록 빠르고 꼭대기 근처에서 느려져요. 오르막에서 힘이 빠지면 **체인 리프트**(일정한 느린 속도)가 끌어올리고, 발사형은 승강장 직후 0.07 구간에서 급가속해요.
- HUD 속도 = 그 유형의 최고 속도 × (v/v최고)^1.7 → 최저점에서 유형 최고 속도, 체인에선 10km/h대
- 🔊 버튼: 브라우저 정책상 첫 클릭 뒤 켜짐, 설정 기억

- 행인: 관절(Group)마다 직계 메시를 **정점색 하나의 지오메트리로 병합**(한 명 65 → 14~17메시). 애니메이션은 Group 회전이라 그대로. 머리·눈 구체 분할도 낮춤. 카메라에서 55 이상 먼 행인은 그림자 생략.
- 트랙 튜브: 분할 F.n×2 → F.n×0.8, 레일 10각→7각, 등뼈 12→8.
- Box 계열 지오메트리는 면마다 그룹 6개라 재질이 하나여도 드로우콜 6번 → `clearGroups()`.
- 바이저 재질의 `transmission` 하나가 **장면 전체 추가 렌더 패스**(+1,500 콜)를 만들고 있었음 → 반투명만 사용.
- 나무는 처음부터 InstancedMesh(300그루 = 14콜)라 빌보드로 바꿀 이유가 없음.

## 3D 모형
- 트랙은 레일 2줄 + 등뼈 + 침목으로, 곡선을 따라가는 좌표계(앞·위·옆)를 조금씩만 돌려 가며 옮겨서 루프·나선에서도 꼬이지 않아요. 열차도 같은 좌표계를 써서 거꾸로 매달릴 때 제대로 뒤집혀요.
- 받침: 스틸은 기둥 + 발판, 우든은 X자 버팀목 트러스, 인버티드·플라잉은 T자 기둥
- 승강장 구조물은 없고, 열차 출발점만 레일이 바로 서 있고 곧은 가장 낮은 곳으로 잡아요
- 열차는 종류별로 다름: 발사형(날렵한 앞코) · 인버티드(다리가 허공) · 플라잉(엎드림) · 스피닝(둥근 통) · 와일드 마우스(쥐 얼굴) · 마인 트레인(굴뚝 광차) · 우든(클래식) · 패밀리(작은 카)
- 행인은 연령·성별·옷차림이 다른 **20종**(아이 · 10대 · 20~40대 · 노인 · 직원 · 커플 …)을 44명에게 돌려 써요. 다리·팔이 걸음에 맞춰 움직이고, 아이는 빠르고 노인은 느려요.

## 화면 구성 (차트 규칙 5가지 반영)
- 패널 맨 위 노란 칸 = **결론 문장** (10개 유형 중 1위/꼴찌, 아니면 전체 중앙값과의 차이)
- 막대 4개(속도 · 높이 · 역회전 비율 · 개수)는 **0부터**, 10개 유형 최댓값 기준이라 유형끼리 비교 가능
- 막대에 마우스 → 값 · 순위 · **분모 n**
- 색은 유형 구분에만 사용, 개장 연대 그래프는 가장 많은 연대만 유형 색
- 열차 달리는 빠르기 = 그 유형의 속도 중앙값에 비례 (재미 요소)
